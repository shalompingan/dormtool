# 中文初稿（Dev.to）

标题：我用纯静态 HTML 做了一个学生工具站，没有框架，没有构建步骤

正文：

我在做一个叫 DormTool 的网站（dormtool.com），给大学生用的一堆免费小工具——宿舍打包清单、房租能不能负担得起的计算器、室友账单分摊、GPA计算器、搬家费用估算这些。现在13个工具，20多篇博客文章。

想在这里聊的不是产品本身，是技术选型和这周踩的一个SEO坑，可能对同样自己一个人搞内容型网站的人有用。

**技术栈刻意选得很"无聊"**

纯静态 HTML/CSS/JS，每个工具就是一个单文件，没有框架，没有后端，没有数据库，用户输入的东西都存在浏览器本地，不上传。部署在 Cloudflare Pages，发布前把所有 HTML 原地压缩（去注释、去空格），没有构建步骤（build step）——压缩本身就是唯一的"构建"。

好处很直接：没有依赖要维护，没有服务器要顾，每个页面加载几乎是瞬时的。代价是所有东西手动改起来比较原始，尤其是压缩后的单行HTML，字符串替换稍微不小心就容易改坏相邻代码，所以现在每次改完压缩文件都会立刻用脚本校验一遍（JSON-LD 用 json.loads 校验、section数和目录对不对得上、div标签数量平不平衡），改一个文件就验证一个，不会攒着一起改完再查。

**这周的一个具体教训**

翻 Google Search Console 数据的时候发现两对文章在抢同一批关键词——一对是两篇讲GPA计算的，一对是两篇讲宿舍清洁的。搜索词几乎一样，流量被拆成两半，两篇排名都不好。

处理方式：把两篇全文通读对比（不能只看标题——标题像不代表内容真的重复，我还差点合并了另外两篇讲房租预算的文章，标题看着像双胞胎，读完发现受众完全不同，就没动）。真正重复的那两对，把弱的一篇里独有的内容合并进强的一篇，弱的一篇做301重定向，再把站内所有指向弱页面的链接都改掉。

还顺手查了另外两对"看起来"也可能重复的文章，这次是先拉了真实关键词数据再决定要不要动手——结果两对都没有重叠，白高兴一场，算是省了一下午的功夫。另外还发现一篇文章在GSC里曝光量是0，一查是压根没提交索引，手动请求索引解决，属于低级失误。

对静态站/内容站，这个流程现在算是走通了：怀疑重复 → 先看真实query数据别凭标题猜 → 通读全文确认 → 合并+重定向+清理内链 → 逐项校验，而不是改完一把梭。

评论区欢迎聊静态站/无框架这条路线的取舍，或者内容型SEO踩过的坑。
